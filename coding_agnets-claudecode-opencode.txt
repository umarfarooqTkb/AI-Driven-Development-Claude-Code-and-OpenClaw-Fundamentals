Claude Code
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
- Claude Code is Anthropic’s agentic coding tool.
- It works inside your terminal, IDE, desktop app, or browser and can understand an entire software project—not just a single code snippet.
- Claude Code is more like a terminal coding agent. 
- Anthropic describes Claude Code as an agentic coding tool that lives in your terminal, understands your codebase, executes routine tasks, explains complex code, 
  and handles Git workflows through natural language.
- Claude Code is an AI coding agent that can inspect, modify, test, and manage a software project through natural-language instructions.

It can:
 * Read and explain your codebase
 * Create and edit files
 * Fix bugs and implement features
 * Run terminal commands
 * Execute tests and analyze errors
 * Refactor code across multiple files 
 * Work with Git and help review changes
 * Automate repetitive development tasks

- You talk to it in the terminal and it reads your entire codebase, understands your project, and writes code.
- You type "Add user authentication to my app": Claude Code reads your existing code, generates the auth module, writes tests, and integrates everything.
- It works in your codebase and can help with coding tasks from the terminal, IDE, web, Slack, or desktop. 
- Anthropic says it can understand codebases, edit files, run tests, work with Git/GitHub/GitLab flows, and help produce pull requests

- In simple words: Claude Code is like a senior AI developer sitting inside your project.
- You can ask: 
- Find the bug in this API and fix it.
- or:
- Refactor this authentication module and add tests.
- It can inspect your files, make changes, run commands, and explain what it did.


For example, inside a project folder you can run: claude
Then ask: Analyze this project and explain its architecture.
or:
Find the cause of the login error, fix it, and run the relevant tests.

- The main difference from the regular Claude chat interface is that Claude Code can directly work with your local project files and development tools, 
  subject to the permissions you approve. 
- It is therefore closer to an AI software-engineering agent than a normal coding chatbot.

OpenCode
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
- Open Code is an open-source AI coding agent that works with your software project. It’s available as a terminal-based interface, desktop app, or IDE extension.
- Open-source coding agent where you can use different models and customize more.
- Its official docs describe it as available through a terminal interface, desktop app, or IDE extension
- Open Code is like an open-source alternative to Claude Code where you get more control and model flexibility.
- You run it inside a project folder, give it instructions in natural language, and it can inspect the codebase, explain code, create or modify files, 
  run terminal commands, troubleshoot errors, and execute tests.

- OpenCode is not an AI model
- OpenCode is the agent or working environment. It connects to an AI model that provides the intelligence.

| Component    | Example                                  |
| ------------ | ---------------------------------------- |
| Coding agent | OpenCode                                 |
| AI provider  | Anthropic, OpenAI, Google                |
| AI model     | Claude, GPT, Gemini                      |
| Project      | Your local application or Git repository |


This is why Open Code has two separate commands: 
/connect = Connects your account or API key to an AI provider.
/models  = Lets you select the model OpenCode should use.

- OpenCode supports numerous cloud providers and local models, so you are not restricted to one AI company.
- you can use openrouter website to use all free and paid models. (see reference section)

Models and providers
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
- OpenCode can connect to providers offering Claude, GPT, Gemini and many other models. It also supports local models.
- You normally configure it like this: /connect
- Select a provider and authenticate.
- Then: /models
- Select the model you want to use.
- You can also use OpenCode Zen, a curated model service maintained by the OpenCode team, instead of configuring providers independently.
- Because OpenCode is model-agnostic, you can point it at whatever gives the best cost-to-quality ratio. 
- Among hosted models, the strongest value as of mid-2026 is DeepSeek V4, which comes in two tiers:
  * deepseek-v4-flash:   $0.14 per 1M input tokens (as low as $0.0028 on a cache hit) and $0.28 per 1M output tokens, with a 1M-token context window
  * deepseek-v4-pro:     the step-up tier when you need stronger reasoning. More capable, still a fraction of frontier pricing.

Uninstall Opencode
======================================================================================================================================================
======================================================================================================================================================
- Since you installed OpenCode using: curl -fsSL https://opencode.ai/install | bash
- you did not install it using apt, so:sudo apt remove opencode     # will not work
- You need to remove the binary and related files manually.

Step 1: Find OpenCode installation location
- Run:which opencode
- You will likely see: /home/umar-farooq/.local/bin/opencode
  or:
- /usr/local/bin/opencode


Step 2: Remove OpenCode binary
- If it is in your home directory:rm ~/.local/bin/opencode
  or
- rm /home/umar-farooq/.opencode/bin/opencode
- If it is in /usr/local/bin: sudo rm /usr/local/bin/opencode

Step 3: Verify removal
- Run:opencode --version
- Expected:Command 'opencode' not found


Step 4: Remove OpenCode configuration (optional)
- Your OpenCode projects may contain:
- opencode.json
- Example:
- find ~/Documents -name "opencode.json"
- Remove if you want:
- rm /path/to/opencode.json


Step 5: Remove OpenCode user files/cache
- Check: ls -la ~/.config
- Look for: opencode
- Remove: rm -rf ~/.config/opencode
- Also check: ls -la ~/.local/share
- Remove if present:rm -rf ~/.local/share/opencode


Step 6: Check npm installation (Important)
- Earlier you installed OpenCode on Windows using: npm install -g opencode-ai
- If you also installed it on Ubuntu through npm, check: npm list -g | grep opencode
- If found: npm uninstall -g opencode-ai

Build and Plan agents
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
- Open Code & Claude Code includes two important built-in working modes.
1. Build mode
2. Plan mode


A good workflow is:
 * Plan mode  → understand and design the solution
 * Build mode → implement and test the solution

You can switch between these agents using the Tab key, or invoke specialized agents with an @ mention.




Plan mode / Plan agent
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
- The Plan mode or agent is primarily for analysis and planning. 
- It can inspect the project, explain the code and propose a solution without immediately changing files. 
- File modifications are denied by default, and shell commands require permission.
- code likhny sy phely, yeh sara plan liky ga aur app to share kary ga
- in plan mode, it decides, how to execute, means planning, then present you the plan before execution, after your review, you will ask agent to fix it.
- it means planning before implementation

- It puts the AI in a "look but do not touch" state
- Instead of doing the work, it writes out a step-by-step plan of what it would do.
- You read the plan, suggest changes, and only then let it start the actual work.

Claude Code:
- In Claude Code /plan = plan mode enabled
- Press Shift+Tab to cycle through permission modes. 
- The first press puts you in auto-accept; the second press puts you in plan mode. 
- In plan mode, the model can read but cannot write: no file edits, no shell commands.

Open Code:
- In Open Code, Press Tab to switch between Build mode (AI can do everything) and Plan mode (AI can only read, not change anything).
- In Plan mode, if you ask it to write or edit something, it will tell you it cannot and wait for you to switch back to Build. 
- Same idea as Claude Code: look first, then act.

++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++

 * Create and edit files

Match the model to the task:
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
- The most capable models are the best thinkers — they plan, reason about tricky code, and handle ambiguity — but they cost the most and use up your limits the fastest. 
- Cheaper (and free) models are perfectly good at following a clear plan: editing files, running tests, reformatting, repetitive changes. 
- The skill is sending each kind of work to the right one.
- For Planning, debugging related task, use the most capable model and for task, where you just have to follow a plan, you can use some lighter/less-expensive model.

- Planning, architecture, "figure out how to do this," debugging something confusing	          >> 	The most capable model you have
- Following a plan you already approved — routine edits, formatting, running tests, boilerplate   >> 	A cheaper or free model

- The expensive part of any task is the thinking — reading the project, deciding the approach, spotting what could go wrong. 
- Once that is a written plan, the rest is "just follow these steps," which a cheap model does fine. 
- So: plan with a strong model, execute with a cheap one. 
- That single move is where most of the cost savings come from, with no loss of quality 

- Two honest caveats. 
- First, cheaper models need clearer instructions — they follow a good plan well but improvise badly, so the weaker the model, the more the plan has to spell out. 
- Second, don't over-optimize: switching models every few minutes costs you attention to save pennies. 
- Default to a strong model, drop to a cheap one for the obvious chores, and leave it there.
- Rule of thumb: 
  a strong model to decide what to do, a cheap model to do it. 
  When a cheap model starts going in circles, that is your signal the task needed the stronger one — switch up, don't keep retrying.







Permission Discipline
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
- Every time these tools want to do something (edit a file, run a command), they ask you for permission first.
- You can skip this and let them do everything without asking, but do not do that when you are starting out. 
- You want to see what the AI is doing before it does it.
- But, After a few sessions, you will notice that some actions are always safe (like reading files or running tests). 
- You can tell the tool to stop asking about those specific actions and auto-approve them. 
- This is the normal arc, not a beginner crutch.
- Anthropic's own product team observes that at launch, users read every single permission request, and over time most graduated to auto-accepting.
— Trust that was earned session by session, which is exactly how you should grant it. 
- In Claude Code, these permissions are saved in .claude/settings.json file
- In Open Code, these permissions are saved in opencode.json file

## Explanation of fields:

| `npm`              | The SDK used to interact with this provider                                                |
| `name`             | Friendly name for the provider                                                             |
| `options.baseURL`  | The endpoint where the provider runtime is listening (for local Ollama, this is localhost) |
| `models`           | List of models exposed by this provider                                                    |
| `models.<id>.name` | Friendly name of the model for OpenCode’s UI                                               |


## How OpenCode uses it
- When you run opencode in a project, OpenCode reads opencode.json.
- It connects to each provider listed.
- You can then list models inside OpenCode using: /models
- Select the model (e.g., Qwen3 Coder Local) to start using it in the project.


## Notes
- Project-specific: You can have a different opencode.json per project.
- Do not delete unless you want OpenCode to forget the connection.
- Editing: If you install a new model in Ollama, you can add its ID to opencode.json so OpenCode can see it.




.claude/settings.json >> Claude Code 
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
- The file .claude/settings.json is a configuration file used by Claude (Anthropic AI) clients. 
- All settings of claude are saved in this file.
- The more you use claude code, more it will be customized itself as per your preferences.
- Its purpose is similar to OpenCode’s opencode.json, but specifically for Claude.

- it stores 
   * user settings
   * runtime preferences
   * connection details for the local or cloud Claude clien
   * API keys (if connecting to Claude cloud)
   * Preferred model version
   * Runtime environment (local vs cloud)
   * UI or CLI preferences
   * Memory and session settings


Key locations:
- Typically found in your home directory or user profile under .claude/.
- Example path: ~/.claude/settings.json


Typical Structure:
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
{
  "api_key": "YOUR_API_KEY",
  "default_model": "claude-2",
  "max_tokens": 1000,
  "temperature": 0.7,
  "memory_enabled": true,
  "local_runtime": {
    "host": "127.0.0.1",
    "port": 11434
  }
}



## How Open Code uses it: When you run a Claude client or app, it reads settings.json to:
- Decide which model to load
- Connect to a local or cloud instance
- Apply user-specific settings like temperature, token limits, or memory
- Changes in this file take effect on next client start.
