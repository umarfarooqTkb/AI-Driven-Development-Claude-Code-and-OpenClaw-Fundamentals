- If a task takes more than [5] mins, use the plan mode first.
- Ask the AI to save the plan to a directory for all important tasks.
- Set permissions set
- Model selection as per your tasks.

Rule of thumb: 
If the task will take more than 10 minutes, use plan mode first. 
For bigger tasks, ask the AI to save the plan to a file (like docs/plans/my-plan.md) so you can come back to it later or share it with a fresh session.



- Do not use "stealth models" in production. they are released under a codename with the maker undisclosed (for example, OpenCode Zen's Big Pickle at the time of writing).
- They are temporary and unannounced.
- A stealth model is a vendor quietly testing something before revealing it. 
- It can change behaviour, get renamed, or disappear with no notice — so do not build habits, defaults, or course/project setups around one.
- Free" can mean you are the product. 
- During a model's free testing window, your prompts and code may be used to train and improve it. 
- Never point a stealth model at anything confidential — client work, private repos, anything under NDA.
- They are fine for throwaway experiments and trying out the workflow. 
- For anything you rely on, prefer a stable, privately-billed model (see the DeepSeek V4 callout below) where the provider, pricing, and data policy are all known 
  and not going to shift under you.

- Plan with a strong model, execute with a cheap one. 
- That single move is where most of the cost savings come from, with no loss of quality 

- Two honest caveats. 
- First, cheaper models need clearer instructions — they follow a good plan well but improvise badly, so the weaker the model, the more the plan has to spell out. 
- Second, don't over-optimize: switching models every few minutes costs you attention to save pennies. 
- Default to a strong model, drop to a cheap one for the obvious chores, and leave it there.

- Rule of thumb: 
  a strong model to decide what to do, a cheap model to do it. 
  When a cheap model starts going in circles, that is your signal the task needed the stronger one — switch up, don't keep retrying.

- Write in your rule files, that do not delete anything from DB, or modify any record. very important in case of context rot.
  because in case of context rot, AI might forget this rule and delte your DB.
  So in case of context rot, stop everything, especially in prod env

- Creat hooks on claude code/open code across the organization.
  create a policy and perform enforcement across the org.
  document it, regularly review it
  compliance is important


CLAUDE.md Best Practices
==============================================================================================================================================================================
- Keep it short
- By default Edit and Delete should be restricted
- Rules written in CLAUDE.md are loaded with every request, if you want that some rules are only loaded when required, then define them in a separate .md file.
- CLAUDE.md file should not be like an encyclopedia, it should be like Table of Contents
- Create code formatting rules for the entire organization, like Team-wise, project-wise, stack-wise
- Keep the file focused and ideally under approximately 200 lines.
- Use direct instructions such as:
  - Use 4-space indentation.
  - Run pytest tests/auth before completing authentication changes.
  - Never expose secrets in logs.
- Avoid vague instructions such as:
  - Write good code.
  - Follow best practices.
  - Make everything secure.

Q. Explain Caching or prompt caching
A. Temporary storage of context

Q. When a cache is invalidated and new cache is created
A. when you change in rule files, system prompts, idle timeout

Q. i am doing a long conversation with a model, caching is working and suddenly i change my model, suppose from sonnet to opus, will it effect the cache and pricing
A. usually yes, your cache will be removed and a new cache will be created and in the next message whole cache will be sent to model, so cost will increase (spike)

Q. Cache is handled at tool level or model level
A. Model level

Q. Diff between Cache hit and Cache miss
A

Q. Causes of Cache miss
A.
The cache expires.
CLAUDE.md, AGENTS.md or another instruction/rule file changes.
Tool or MCP definitions change.
The selected model or provider changes.
Thinking or reasoning settings change.
Tool-choice configuration changes.
Images or documents are added or removed.
Earlier conversation history is edited, rewound, forked or reordered.
A new session produces a differently structured prompt.
